The Compose checks cover entry and exit, Android Back, simulated keyboard focus restoration, restored mode, manual lyric scrolling, stale lyrics, request protection, compact and large-text layouts, and the accessible reconnecting-status icon. They execute the real SQL policy/migrations/maintenance and owned Music JXA at its explicit native API boundary. Coverage includes protected current requests, Play next versus protected Play now, expiry/replay boundaries, protocol validation, queue waits and ordered analytics persistence. Both workflow files pass actionlint 1.7.12.

On 28 October 2026 the CI workflows gained Gradle user-home and Robolectric Maven caches for the Remote jobs, a Swift module cache for the Host check job, and a commit-pinned `SOURCE_DATE_EPOCH` so build timestamps are deterministic per revision. `apps/remote/gradle.properties` now enables the Gradle build cache and configuration cache. The edited workflows passed actionlint 1.7.12 and Prettier through the portable gate. Two consecutive `apps/remote/check.cmd` runs passed on Windows: the first stored the configuration cache entry in 1m46s, the second reused it in 8s with all checks intact. Cache-restored wall-clock savings on GitHub-hosted runners remain to be observed after the next pushes; no runner timing claim is made yet.

## Packaging and security

No packaged APK, Host archive, source tarball or generated `dist/artifacts.json` is present in this checkout; the current check produced compile/lint/test outputs only. Packaging remains a separate step after the visible-version decision. Dev and CI updates are disabled by default, and neither profile is a Production release.

For the final dependency state, system Bun 1.4.4 audit reported no vulnerabilities in 30 development packages, and an OSV batch query returned no findings for 71 resolved native Maven coordinates. Ten XML/plist source files parsed; a scoped private-key/GitHub/AWS credential-pattern scan returned no matches. Query/results are under `.cache/security`. These narrow scans do not prove absence of all vulnerabilities or credentials. Browser CSP/cookie-CSRF checks are inapplicable to these native apps: Host serves no HTML and uses no browser cookies. Native/transport/storage security tests remain applicable. Pattern/database/unit checks do not establish a complete security audit.

An earlier Windows external-boundary probe mirrored Catalog.swift's discovery/token-selection URLs and successfully searched Apple's public catalog without Apple account credentials or paid developer keys. Its sanitized metadata is under `.cache/catalog-probe-result.json`. This does not execute the Swift actor or prove catalog playback/native queue control. The web-token adapter remains undocumented and changeable.
